### 发现（待修复）

1. **R1 / P1：工程恢复入口先验证损坏快照，导致恢复命令不可达。** `tools/LightHub.HardwareProbe/Program.cs:40` 对所有命令调用默认 `ReadSnapshot()`；该调用在 `Core/OnboardDevice.cs:84` 执行 Validate，CRC 损坏或活动槽标志失效即抛异常。若启用时目录部分写入后进程被终止，按文档执行 `restore ENDPOINT BACKUP --execute` 会在到达第 101–106 行的 TransactionEngine.Restore 前退出，尽管事务恢复本身支持 `allowCorrupt: true`。普通应用又没有目录 EnableProfile 许可，因此该工具提供的目录恢复途径被阻断。应让 restore 的初始读取允许损坏，保留身份/几何/固件/连接许可校验，并以有效备份作为恢复目标；用目录 CRC 损坏及非法目录标志两种模拟输入验证整个命令入口。此项为调用链静态确认，未对实机制造损坏。
2. **R2 / P2：warm-dpi 缺少显式执行开关。** `tools/LightHub.HardwareProbe/Program.cs:24` 接受 `warm-dpi ENDPOINT`，随后第 78–79 行直接写传感器 DPI；`--cycles` 也只是计数参数。它违反本审查包及文件开头“无显式 execute 参数不写”的约定。应要求独立执行参数，无该参数时拒绝写入或只输出计划，并测试无开关时零写调用。未执行此实机命令。
3. **R3 / P2：warm-dpi 的异常路径不尝试恢复，且不留下持久恢复标记。** `tools/LightHub.HardwareProbe/Program.cs:78–87` 只有正常循环第二次 SetCurrentDpi 才恢复初值；finally 仅 ReadTelemetry 后抛错。`OnboardDevice.SetCurrentDpi` 在协议写入后还有读回，因此第一次调用可在设备已改变 DPI 后因读回超时抛出，直接跳过恢复调用；Ctrl+C 也没有 activation 分支的处理器。此时既无恢复备份/待恢复标记，成功结果文件也尚未写出。应在受控退出和写后读回失败时，在确认连接身份及运行态仍匹配后尝试恢复；无法确认恢复则持久记录初值和未恢复状态，避免盲目跨重连写回。新增模拟“写成功、读回失败”及中断覆盖。此项为静态确认，未进行实机故障注入。
4. **R4 / P2：制品校验只检查归档存在且非空。** `tools/verify-package.ps1:32–33` 不读取 ZIP/tar.gz 内容，也不与已校验目录的清单比较；工作流实际上传的正是这些归档。因此陈旧、损坏或含额外私有文件的归档可以在展开目录正确时通过。隔离复现：创建满足必需文件/摘要要求的合成目录，将同名 `.zip` 写为文本 `NOT A ZIP FILE`，脚本仍输出 `Verified 7 package files`。应安全读取实际归档，核对成员集合及摘要，拒绝坏归档、越界路径、额外文件和归档/目录不一致，并对 tar.gz 做同等校验。
