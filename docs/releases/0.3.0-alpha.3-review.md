### 发现（未修复）

1. **A3-R1 / P2：返回扇区集合按编号大小而非使用顺序筛选。** `src/LightHub.Application/OnboardMacroPacker.cs:82–83` 使用 `p.Key <= lastUsed`，但参数为有序列表，未要求或校验升序。实测 100 个合法 delay、扇区 `[9,6,7]`、大小 255：StartSector=9，却仅返回扇区 6，丢失起始扇区和跳转记录；单个 delay 反而返回 9/6/7，后两个未使用且 CRC 未更新。应按 `macroSectorIds.Take(sectorIndex + 1)` 返回准确使用集合，或在入口明确拒绝不符合要求的顺序；增加非升序和稀疏 ID 覆盖。
2. **A3-R2 / P2：恢复引导按钮遗漏统一异常处理，失败可成为未处理 UI 异常。** `src/LightHub.Desktop/MainWindow.axaml.cs:177–179` 的 async void 直接 await Restore；旧文件选择和备份列表入口均经 Safe。备份存在但损坏、显示后被删除，或恢复因断连/许可被拒绝，都会从 BackupFile.Load/Model.Run 抛出并逃出新事件处理器。应通过 Safe 包裹，保留确认及底层门控，补充坏备份和恢复失败时界面可继续使用的测试。本项为调用链静态确认，未在实机触发异常。
3. **A3-R3 / P2：解析器未检查声明的宏格式，未知格式可能被误报为完成。** `src/LightHub.Core/MacroFormat.cs:52` 的 Decode 没有检查 Layout.MemoryModel/MacroFormat，CLI、编辑器和诊断调用方也未限制。该实现明确只解释 memory model 1 / macro format 1，但实测一个通过 Snapshot.Validate、MacroFormat=2 的快照仍将 `[43 00 04 44 00 04 FF]` 报为 `complete (1 steps)`。生产写权限关闭不会阻止这条只读误判路径。应对不支持的格式返回明确状态，调用方同步展示未知格式，测试不同 memory model/macro format。
4. **A3-R4 / P2：键名输出会误标或丢掉实际键值。** `src/LightHub.Core/MacroFormat.cs:135–144` 把 0x1E–0x27 统一从字符 '1' 相加，导致 0x27（数字 0）输出冒号；未知键带修饰键时，Prefix 非空使原始 usage 的回退失效，例如 `KeyName(1,0x74)` 仅返回 `ctrl+`。这直接影响新 CLI 和板载宏详情，无法忠实说明动作。应单独处理 0x27，并让未知基础键独立保留 usage，再拼修饰键；增加数字 0 和带修饰键未知 usage 的断言。
5. **A3-R5 / P2：UTF-16 名称误拒合法代理对，同时放过 C1 控制字符。** `src/LightHub.Core/ProfileName.cs:25` 拒绝所有代理项而非仅孤立代理项，合法 `A😀` 实测返回 null；仅检查 `<0x20`/0x7F 又使 `A\u0085B` 被原样接受，违反控制字符拒绝要求。应按 UTF-16 配对验证并检查完整控制字符类别，在非法代理项时返回无名称；补充合法代理对、孤立高/低代理项、C1 控制字符测试。
6. **A3-R6 / P3：4096 事件上限实际允许返回 4097 项。** `src/LightHub.Core/MacroFormat.cs:65` 在下一轮用 `> MaxEvents` 检查，已多加入一项才终止。隔离的 4096 字节扇区流复现返回 truncated、Steps.Count=4097。应在加入事件前执行数量限制，保留恰好 4096 事件后 END 的合法情况，并覆盖上限及上限+1。
7. **A3-R7 / P3：EncodedLength 绕过形状校验。** `src/LightHub.Application/OnboardMacroPacker.cs:43–48` 直接调用 EventBytes；实测 SchemaVersion=999、单个 delay 返回长度 4，而非 Format；空 Events 等还可能抛未经规范化的异常。Pack 的 ValidateShape 不覆盖这个独立公共入口。应在长度计算前执行同样的 ValidateShape，并对未知版本、未知 execution、非法 usage、空 Events 引用加断言。
