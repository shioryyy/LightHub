# 宏编辑开发批次：2026-09-12

基于设计 1.1，在现有工程增量实现。应用版本仍为 `0.3.0-alpha.1` 开发状态；本记录不代表 GitHub Release 或稳定发布。

## 交付边界

E1/E2 的本地功能已落地：Application 中独立的 MacroLibrary、MacroValidator 和模型；Desktop 中独立 MacroEditorViewModel/视图。Workspace 仅负责组合与语言同步。没有在 Core/Hid 引入系统输入注入、服务、自启或应用检测。

支持命名、键盘按下/释放/延时、增删排序和复制步骤、宏复制、导入副本、导出、无效草稿保留、回收和找回。保存使用原子替换、宏库文件租约、内容摘要冲突检查；更高版本、未知字段和错误文件不会静默覆盖。当前预设 v1 不支持语义宏引用；回收可通过引用接口阻止删除，遇到未知预设格式默认阻止。后续引用写入端必须共同使用宏库租约。

本地保存与设备应用在界面明确区分。宏执行、绑定、容量评估、板载宏恢复和软件运行器未实现，能力提示与禁用按钮保持这一事实。已有设备写权限未扩大。

## GPW1 只读触发查询

环境：Windows NT 10.0.26200.0，设备报告名称 `G Pro Wireless Gaming Mouse`，C539 接收器槽 1。调用新版 CLI 的 list 和 trigger-inspect；六次功能查找均成功返回索引 0：

| 功能 | 本次结果 |
| --- | --- |
| 0x1B00 / 0x1B01 / 0x1B02 / 0x1B03 / 0x1B04 | 均 absent，index=0，version=0 |
| 0x8010 | absent，index=0，version=0 |

无控制条目；`readOnly=true`，`executionVerified=false`。只查询功能，不修改配置、不捕获或触发宏。随后尝试完整 inspect 时，设备再次返回此前出现的 `HID++ error 0x09`，因此本次没有取得新固件版本读数；不能沿用旧记录伪装成本次固件核验。

结论仅针对当时连接与查询结果：所查询的通用 HID++ 触发功能不可用。它不证明 GPW1 永远无法做软件宏，也不证明其他型号相同。后续 T0 应验证 Windows Raw Input 是否能区分物理来源/按键，并单独解决原动作抑制与恢复。没有受控按下/释放、休眠、重连和停止证据前，不开放运行器。
