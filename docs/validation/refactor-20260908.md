## 已实现范围

Application 类库承接事务、备份、本地预设与会话编排。桌面端与 CLI 共用
`DeviceSession` 的读取、保存、启用、试用和恢复服务；Hid 通过 `IDeviceAccess`
提供连接与租约。协议编解码仍在 Core，桌面编辑状态仍有进一步拆分空间。

保存不再默认启用槽位，活动槽编辑保留当前有效 DPI；删除当前档位要求明确替代。
临时 DPI 具有设备代次、状态核对、恢复检查和崩溃标记。启动不恢复旧试用、不写设备。
权限按固件、连接与操作分开，GPW1 限定 BOT 74.02.0026 / C539 receiver。
主动启用槽位尚无独立证据，保持禁用，不能把按钮存在当作功能通过验收。

本地预设支持命名、复制保存、重命名、导入导出和草稿载入。物理映射目前仅有
GPW1，其他跨型号映射明确拒绝。草稿暂存及恢复不写设备。备份支持名称、置顶、
里程碑、手动保留十份、回收与找回、永久删除独立确认；没有自动清理。

宏已有本地语义验证器，**没有宏编辑器、设备编译器或宏写入能力**。
G-Shift、灯光、常驻软件模式和应用切换没有在本轮实现。

## 硬件状态

本轮前段 CLI `list` 收到 `HID C539, slot 1: HID++ error 0x09, feature 0, function 0`，
列表为空。后续最终 Windows 包成功发现 GPW1，固件 BOT 74.02.0026 / C539 接收器。
已完成 inspect、before backup、非活动槽 smoke/restore、dpi-smoke、独立进程 after backup：

- 非活动扇区 5 修改 DPI、回报率和末尾按键，保存完整验证 6684 ms。
- DPI 编辑会将勾选的有效档位压缩为连续设备槽位；取消中间档位不会因固件连续性要求而无法保存。
- 恢复完整验证 8988 ms；没有启用备用槽，没有修改活动槽或当前档位。
- 临时 DPI 设置含打开会话 467 ms，恢复原始值后确认板载内存和状态未变。
- 前后备份 payload 及其 SHA256 完全一致：16 个扇区、mode 1、活动扇区 1、DPI index 2、sensor DPI 1600。
- 个人备份仅保留于本地 artifacts 和应用数据目录，不进入源码或制品。

上述为单次实际观测，不能当作统计性能或物理按键/断电持久性验收。
不对唯一日用鼠标执行写入中断电试验。

## 软件验证

本轮已有 77 项 Release 测试通过，包括两个真实进程争用备份锁、Windows 阻止日志
替换后的收尾失败、外部 DPI 冲突、未知动作拒绝、回收找回与语言切换保留草稿。
Avalonia headless 已生成 960x680、1120x800、1440x1000 的中英文截图，人工检查了
板载设置、预设和备份页面。Headless 截图不等于原生平台完整交互验收。

Windows 自包含包已完成一次原生启动观测。单次启动到 input-idle 约 396 ms，
60 秒观测私有内存约 135.5 MiB、平均 CPU 约 0.18%。使用 `tools/measure-desktop.ps1`
的 demo 模式，期间有构建活动；此结果仅是进程冒烟证据，不是 p95、真实 HID 工作流
或受控性能验收。包中 SOURCE-MANIFEST.json 记录源码内容，SHA256SUMS.txt 记录制品。

迁移后的旧 `LightHub-community` 仅剩空目录；自动审批策略拦截了空目录清理，未再处理。

GitHub Actions 的 Ubuntu job 后续需重新运行确认；发布脚本已改用 runner 原生 tar 并
显式保留 Unix 启动权限，避免 Windows 生成的 PowerShell Tar 归档与 Linux runner 差异。
