# 06 宏与可选运行器实施方案

设计日期：2026-09-11，属于设计基线 1.1。2026-09-12 已实现 E1/E2 的本地功能及 T0 只读预检，验证边界见[本批记录](../validation/macros-20260912.md)。O/R 执行分支和完整 T0 仍未通过；本地编辑不代表可执行。

## 1. 决策变更记录

修订 D04、D08，保留 D01 的板载优先和 D11 的写入恢复门槛。原因是固定配置需求、宏需求与是否接受常驻彼此独立；旧表述容易把首版范围误当成永久限制。依据是维护者确认的方向和现有代码边界，不是新的社区用户比例调查。

| 项目 | 原基线 | 1.1 决策及用户行为变化 |
| --- | --- | --- |
| 宏编辑 | 与受限板载宏放在同一交付阶段 | 作为核心本地编辑能力独立交付；无需接设备或安装输入监听 |
| 执行 | 首批仅板载，软件宏待另行决策 | 板载和可选软件运行器独立推进；能力不支持时明确拒绝，不自动换后端 |
| 常驻 | 首版不做，部分文档语气像永久禁止 | 板载功能仍无需常驻；软件宏只在用户启用期间运行，默认不自启 |
| 自动切换 | 与软件模式一起讨论 | 单独后置、默认关闭；固定软件配置不需要应用检测 |
| 关闭窗口 | 退出工具 | 默认停止并退出；未来只有显式选择才保留可见运行器 |

未采用方案：删除宏（不满足需求）；复制 G HUB 的应用优先入口（增加固定配置成本）；立即安装系统服务/全局钩子（触发技术尚未验证）；全量重写或更换 UI 框架（没有证据表明是必要条件）。沿用 .NET/C#/Avalonia/HidSharp，平台注入仅在适配层按需引入，不让 Core 引用系统输入 API。

数据兼容：本次不改变文件格式。LightHub/2 备份和 LocalPreset v1 保持读取兼容；已有 LocalMacro v1 的含义保留。未来任何格式升级必须保留原文件和旧读取器。验收关联 A01—A24，以及下文 E01—E05、T01—T05、R01—R06。

当前官网默认值未在本次重新核查。历史社区材料仍见 PRODUCT-STRATEGY；不以“多数人讨厌应用配置”或“G HUB 强制自动切换”为本决策前提。

## 3. 数据与界面契约

- 宏定义：UUID、schemaVersion、名称、execution=single、down/up/delay 事件；没有设备地址、扇区指针或应用路径。沿用 256 事件、30 秒显式延时、单延时 1—10000 ms、最多 6 个普通键的上限；这不是设备容量或实测执行时间。
- 宏草稿：允许暂时存在未配对按键，逐项标记错误；无效草稿不得标记为可执行宏。关闭时保存草稿、放弃或取消，不能静默丢失。
- 宏文件：macros/<uuid>.lhmacro；最多 2 MiB、JSON 深度 32，限制事件数并拒绝未知/重复字段、更高版本和路径越界。损坏文件单独报告，不让一个文件使整个列表不可用，也不自动覆盖原件。
- 软件配置：命名配置独立于应用，绑定引用宏 ID 和固定修订/摘要；运行中的版本不可被宏库编辑悄悄替换。应用关联另存规则对象，不能嵌入宏。
- 设备绑定：经目标设备能力评估后编译为板载动作；LocalPreset v1 原始四字节绑定不能承载语义宏引用。后续 v2 须区分标准动作和宏引用；旧版本拒绝 v2，导出完整依赖闭包或明确报缺失引用。
- 删除与导入：引用中的宏阻止删除，先显式解除；未引用宏进入可恢复回收区。导入相同 ID 不默认覆盖，提供作为副本导入；共享文件不得自动启动运行器或修改应用规则。

编辑器提供新建、命名、步骤增删/排序/复制、按下/释放、延时、宏复制、导入导出。第一批不提供全局录制、脚本、无限循环、鼠标轨迹、启动程序或自动执行预览。

每个宏显示：本地是否保存、目标执行方式、设备/平台能力原因、容量是否已知、关闭软件后是否有效。没有编译器时容量显示“未知，未验证”，不能按事件数估算为可写。E2 可以显示按键绑定入口和禁止原因；只有执行后端通过门槛才允许真正应用绑定。本地按钮标为“保存到宏库”，不叫“应用到鼠标”。

## 5. T0 触发验证计划

先核对描述符、物理设备身份和公开协议，记录 OS、固件、连接方式和驱动版本。在受控本地测试窗口由测试者逐个按下/释放目标按键，不通过全局录制采集日常输入。

候选路径按顺序验证：设备范围的 HID++ 主动事件；Windows Raw Input 的设备标识与按键事件；若需要阻止原动作，核实设备 diversion/remap 能力。Raw Input 本身不能作为“已经抑制原动作”的证据。低级全局钩子不是默认降级路径，必须另行说明捕获范围和权限。

| ID | 证据与判定 |
| --- | --- |
| T01 | 所需按键是否有独立、可归属到物理设备/槽位的按下和释放事件；列出无法区分的按键，不用型号猜测 |
| T02 | 是否需要临时改变映射/模式才能触发；关闭时如何恢复，崩溃后的风险；原动作和板载宏是否同时触发；不存在可验证抑制时仅可声明非独占原型，不开放替换绑定 |
| T03 | 一个读取器路由响应与事件，不串槽、不吞事件；配置操作期间暂停触发，持久化前停止执行；租约竞争时明确拒绝 |
| T04 | 拔插、休眠、权限丢失、应用退出后不重放；恢复订阅前重新核对身份与能力；默认要求用户重新启用 |
| T05 | 记录事件遗漏/重复、时延及空闲 CPU/内存、无线休眠行为；不为保持事件通道增加无依据的定时 HID 查询 |

初始可行性通过要求：一个非主键可重复地产生正确事件，目标身份明确，原动作处理有证据，所有停止路径可解释，日用设备可恢复。证据不足则 R1 阻塞，保留 E1/E2；不能仅因 Windows SendInput 可调用就判定方案可行。

输入注入另做受控验证：初版仅同权限普通桌面应用，不承诺提权窗口、安全桌面、游戏或反作弊环境。Linux 需分别验证 X11/Wayland 与设备权限，macOS 需验证辅助功能等权限；未经验证平台只提供本地编辑，不静默申请额外权限。

## 6. 软件运行器状态与验收

候选端口为 ITriggerSource（身份、连接代次、按下/释放）、IInputSink（输出与持有键释放）、IMacroCapabilityEvaluator（支持/原因/限制）、单调时钟与可取消调度器。名称是实现入口建议，不表示已有接口。使用 fake 输入接收端验证调度，自动化测试不注入真实桌面。

初版每设备串行执行一个宏；运行中重复触发直接忽略并显示忙碌，不无限排队，不支持重入或按住连发。Stop 优先于后续事件；中断延时，清空队列，再释放运行器持有的键。执行期间固定不可变配置版本；手动切换配置先停止旧执行。物理同键与注入键相互作用必须实测并记录限制，不能声称能隔离所有应用的全局键状态。

| ID | 必须验证的结果 |
| --- | --- |
| R01 | 开机/启动默认 Off，无服务和新增启动项；启用运行器不自动启用应用规则；普通板载工作流独立可用 |
| R02 | 切换前台应用不改变固定配置或 DPI；未显式启用的宏库修改不影响执行快照 |
| R03 | Stop、关闭、注入失败、断连、休眠、权限撤销取消延时和剩余事件，释放已持有按键；fake 精确检查顺序，实机受控窗口验证 |
| R04 | 连点、长按、重复报告、重连、配置切换不并发重入、不重放旧命令；板载事务取得通道前运行器已停止 |
| R05 | 窗口关闭默认停止；显式继续后状态与停止入口可见；全部退出结束运行器；故障/强杀不宣称绝对释放，重启不续播 |
| R06 | 输出实测触发时延、执行误差、空闲/运行 CPU 与内存、唤醒及功耗相关观察；启用后的成本单列，不引用板载空闲预算冒充运行器测量 |

资源门槛在 T0 报告中提出并在 R1 开发前冻结；目前无数据，不承诺“几乎零开销”。板载 1.0 原门槛不降低，运行器可单独标为实验性；一项平台通过不提升其他平台等级。
