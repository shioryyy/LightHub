# 05 交付、验收与治理

状态：设计基线。执行顺序以门槛为准，不承诺没有硬件依据的日历日期。

## 1. 里程碑与退出条件

| 阶段 | 交付物 | 完成条件 | 依赖 |

新的公开 alpha 在 M0—M3 达到相应范围后发布；现有 `0.2.0-alpha.1` 是历史验证基线，不自动被认定满足新方案。beta 和稳定版本只报告实际通过的阶段，不通过改标签替代验证。

只有 GPW1 时，M0—M3及受支持的 M4 工作仍可推进。更多型号和平台的发布门槛等待贡献者或测试设备，不强行启用驱动。对唯一日用鼠标不做写入中断电、擦除未知扇区或固件试验。

## 2. 需求追踪与验收

所有验收项在实现任务中附测试名/报告路径，未完成保持未通过，不预先打勾。

验收状态按模拟测试和具体平台/设备组合分别记录。M2、M3 的阶段完成要求对应模拟测试及 GPW1 Windows 可执行的实机项通过；A14 的多设备实机部分、A17 的其他平台原生部分等留待 M6，不因此把整个验收项标成全部通过。公开 alpha 必须列出这些剩余验证范围。

| ID | 决策/工作流 | 必须验证的结果 | 方式 |
| --- | --- | --- | --- |
| A01 | D02 / W01 | 启动、选择、扫描、重连无配置变更请求；host 模式保留 | 命令记录型 fake transport＋实机只读对照 |
| A02 | D03 / W02 | 保存备用槽不改变活动槽、模式、当前 DPI 档位 | 合成事务测试＋GPW1前后快照与人工速度检查 |
| A03 | D03 / W03 | 按键编辑不重设当前有效 DPI；默认档位变化不隐式启用 | 覆盖当前档位不同于默认档位的测试 |
| A04 | D03 / W03 | 删除当前档位必须明确指定替代；失败时没有写请求 | UI 与应用层契约测试 |
| A05 | D12 / W04 | 临时调整读回一致，不改变板载内存、不创建闪存保存备份 | 模拟＋有界实机设置/恢复 |
| A06 | D12 / W04 | 结束试用只在设备代次和状态匹配时恢复；失配不回写 | 断连、替换设备、外部变化、崩溃标记测试 |
| A07 | D03 / W05 | 切设备/关闭不静默丢稿；提交中关闭不截断写入 | Headless UI＋原生交互 |
| A08 | D11 / W06 | 冲突保留草稿且阻止覆盖，重新加载需重新校验 | 应用层故障注入 |
| A09 | D11 / W07 | 部分写入/CRC失败不重试；恢复引用保留 | 每个写阶段故障注入，不在日用鼠标上断电注入 |
| A10 | D09 | 跨型号预设不携带单元身份或原始扇区；不兼容项不静默丢弃 | schema、映射、导入错误测试 |
| A11 | D10 | 旧备份兼容、未知新版本拒绝覆盖、迁移失败保留原件 | 文件系统测试＋历史合成样本 |
| A12 | D07 | 图示、型号名、相同 PID 不单独获得写权限 | 支持策略负向测试 |
| A13 | D06 | UI/CLI 在相同输入下执行相同计划和错误规则 | 应用服务集成测试 |
| A14 | D06 | 多槽不串包，不同设备不混淆，锁顺序无死锁 | 路由与并发模拟＋多设备实机 |
| A15 | D11 | 成功与真实验证程度一致；日志收尾失败不自动重写 | 持久化故障注入 |
| A16 | D13 | 清理保留最近10份及恢复/置顶/里程碑/损坏备份 | 多单元、多引用与时间边界测试 |
| A17 | D14 | 回收可撤销，永久删除独立确认，目录跳转不越界 | 文件系统＋UI测试，各平台原生验证 |
| A18 | D13 | 写事务和删除互斥，预览后新增保护仍阻止删除 | 两个实际测试进程的锁竞争，不只同进程模拟 |
| A19 | D08 | 宏容量、时长、按键平衡、指针和共享引用检查有效 | 独立已知向量、畸形数据、边界/随机输入 |
| A20 | D08 / D11 | 宏部分写入后可恢复，未知扇区不损坏 | 事务阶段故障矩阵与备用空间模拟 |
| A21 | D08 | 实际触发顺序、延时、释放及断电后结果符合声明 | 受控输入窗口实机，记录固件和驱动版本 |
| A22 | D15 | 断网完成核心工作流；普通退出无必要后台进程 | 原生运行与进程/网络行为检查 |
| A23 | D16 | 目标平台包原生启动、权限、安装、读写、休眠、卸载通过 | 每平台独立报告；CI 不替代 HID 实机 |
| A24 | D17 | 发布包可追溯、依赖许可齐全、不含私人备份/路径/凭据 | 包内容审计、校验和、源码重建 |

对行为变更测试必须包含“不允许发生的副作用”，不能只测新值写入成功。至少一次代码审查需由未参与对应驱动实现的人完成；尚无审查者时保持未完成状态。

## 3. 性能与资源预算

以下是目标预算，不是当前测量结果。初始参考环境为 Windows 11 x64、16 GiB 及以上内存、SSD、GPW1 接收器、Release 自包含构建，关闭其他鼠标管理软件。记录 CPU、OS build、鼠标固件、USB连接、屏幕缩放及是否冷启动。

| 指标 | 初始目标 | 测量规则 |
| --- | --- | --- |
| 命令受理反馈 | p95 <=100 ms | 不含硬件完成；UI必须显示忙碌/验证状态 |
| 首个可交互窗口 | p95 <=2 s | 不等待硬件发现；10次独立进程启动记录，区分首次系统缓存状态 |
| 窗口空闲资源 | 私有内存 <=250 MiB，60秒平均CPU <=0.5% | 设备读取完成、日志稳定、无编辑、无测试并发；使用约定采样工具 |
| 温连接临时DPI | p95 <=300 ms | 20组有界设置/恢复，含协议确认，不包括250ms输入合并窗口 |
| 冷连接临时DPI | p95 <=1 s | 包括打开、身份/能力、设置和回读；未达到则先剖析会话成本 |
| 标准板载保存 | 首轮工程目标 <=8 s | 单槽GPW1完整检查；记录3次必要功能回归的每阶段时间和最大值，不拿3次样本宣称可靠p95 |
| 备份历史 | 1000条时操作可立即受理，列表异步载入且不阻塞输入 | 真实磁盘合成样本；分页/虚拟化不截断可管理历史 |
| 离线分发体积 | Windows压缩包 <=120 MiB 的工程目标 | 带运行时与许可证；不得通过删除恢复功能达标 |

参考机器预算未达标时，alpha 必须报告偏差并建立处理项；稳定发布需要达标或正式修订预算与原因。Linux/macOS 的资源数字在各自原生基线记录，不能直接宣称继承 Windows 测量。

现有约120ms温连接DPI和约6.1秒完整写入只是此前单次观测。性能回归不通过高频反复写闪存制造样本，先用模拟传输剖析，再做有限必要实机验证。

## 4. 平台与型号质量等级

初始原生验收环境选定为 Windows 11 x64 的受支持维护版本、Ubuntu 24.04 LTS x64/X11、macOS 26 ARM64。发布前核对 .NET、Avalonia 与系统仍处于支持范围并记录具体版本；这些选择不代表本项目已在对应系统运行。

| 等级 | 最低证据 | 对外表述 |
| --- | --- | --- |
| 构建候选 | 恢复依赖、编译/打包成功 | 可构建/实验包，不宣称原生可用 |
| 原生预览 | 原生启动、布局/文件选择/权限基础测试 | 实验性平台；每项设备变更独立受限 |
| 操作已验证 | 指定设备/固件/传输组合的相关回读、恢复和物理测试 | 准确列出已验证操作，其他能力仍只读 |
| 平台稳定 | 原生安装/升级/卸载、基础操作、至少一个家族实机、生命周期、签名与可访问性门槛 | 只对该平台与其支持矩阵标为稳定 |

Windows 稳定1.0额外要求至少三个鼠标家族的基础板载读写/恢复通过，例如GPW、G305/G304家族、G502家族；列举仅为候选，不是兼容声明。Linux/macOS各自至少一个家族通过完整平台门槛后才发稳定包。ARM64 Windows、Linux ARM64、macOS x64和Wayland为独立验证扩展。

至少包含：物理按键、活动与备用槽、断电后保留、休眠唤醒、接收器拔插、有线/无线差异，以及多接收器不串设备。单型号单固件的证据不自动覆盖整个家族所有固件。

## 5. 开源协作与发布

- 源代码采用 MIT；不默认引入额外贡献许可协议。贡献需声明来源及可分发授权，第三方代码/素材按各自许可证保留署名。
- CI 执行锁定还原、Release构建、核心与headless测试、依赖清单、包扫描及源码包重建。无USB硬件的runner只证明这些步骤。
- 每项设备能力提交脱敏诊断、协议来源、驱动版本、操作范围、测试结果和恢复方式。完整备份不是公开提交的默认材料。
- 设备写入、宏分配、身份校验、恢复、删除保护等变更需要专门审查；UI文字调整不增加无关测试负担。
- Windows稳定包需要有效签名；macOS稳定包需要规范app包、签名及公证；Linux包提供完整校验和、来源和可验证的发布签名。证书/凭据缺失是发布依赖，不影响本地功能研发。
- 发布制品包含版本、目标平台、提交标识、依赖锁与许可证、SHA256清单、支持矩阵、已知问题、迁移/回滚说明。源码包不得含用户备份或构建缓存。
- 软件升级只迁移本地数据，不写设备、不自动启用新能力、不重新绑定预设。回滚程序需能保留旧数据副本；不能用旧版本覆盖更高版本格式。
- 用户主动下载安装更新。首版不做自动下载、静默更新和强制升级；安全修复通过发行说明和项目渠道公告。
- GitHub仓库、远程地址、CI运行和发行页尚未建立时保持这一事实。规划文档不代表已经提交、推送或发布。

## 6. 风险与应对

| 风险 | 已确定的处理 |
| --- | --- |
| 只有GPW1，无法证明其他型号 | 协议与多布局模拟先行；贡献者/测试设备补证；保持对应操作关闭 |
| 宏布局或执行语义不明 | 先只读；安全分配和恢复不成立就不开放；稳定宏门槛不靠静默缩减假装完成 |
| 无法排除外部管理软件 | 已知进程阻止＋快照冲突校验；明确锁只协调LightHub |
| 平台HID/权限差异 | HidSharp适配隔离；原生门槛；必要时仅替换传输实现 |
| 方案范围膨胀 | 软件模式、生态硬件、云功能独立立项；M5不绑架基础范围 |
| 存储删除或迁移损坏恢复材料 | 保护引用、原子文件、迁移副本、回收区、跨进程锁与故障测试 |
| UI状态复杂度增长 | 应用层状态机、命令前置条件、独立ViewModel，不靠更多布尔开关叠加 |
| 无独立审查/签名资源 | alpha透明标注；稳定发布条件保持未完成，不虚构完成 |

## 7. 开始实施前的确认清单

产品和技术决定已在本方案中敲定，不再留“选一个框架”“是否自动切换”之类悬而未决的项。实施前实际需要的材料是可复现源码基线、独立测试数据、可用工具链及阶段任务清单；硬件、签名和审查属于后续证据/资源依赖。

首先实施 M0—M1，完成后审查 A01、A12—A15 的应用边界与模拟测试，并确认 A02—A04 的行为测试计划；M2 再完成对应工作流验收，随后进入预设扩展。不以增加更多页面替代边界修正。当前已有61项测试是回归起点，本方案新增验收项尚未执行。
