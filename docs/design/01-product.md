# 01 产品需求与范围

状态：设计基线。总决策见[方案入口](README.md)。本文件规定目标行为，不宣称已经实现。

## 1. 用户与任务

| 用户 | 核心任务 | 首版处理 |
| --- | --- | --- |
| 一次设置型 | 调 DPI、改侧键、保存后卸载或退出管理软件 | 主工作流，必须完整可用 |
| 手动多配置型 | 保留办公、游戏等预设，手动选择和写入板载槽 | 本地预设库与显式启用，不绑定应用 |
| 基础宏用户 | 用鼠标执行短按键序列，不希望开常驻 | 只开放有证据的板载宏子集 |
| 软件自动化用户 | 按应用切换、循环宏、脚本、跨设备动作 | 后续独立立项；首版不以不完整界面承诺支持 |
| 其他型号贡献者 | 获取脱敏诊断、提交布局与测试结果 | 只读发现和可复现验证流程 |

设备名称、按键位置、默认动作、当前动作必须分开。某个侧键被改成 Ctrl+C 后，它的位置名称仍是侧键，不能变成“复制键”。没有核实的位置保持中性编号，并明确没有已验证位置图。

## 2. 版本范围

### P0：首个公开 alpha

必须交付一个完整的标准鼠标板载流程：发现与选择设备、读取能力、DPI 档位/回报率/基本按键编辑、主键保护、保存与启用分离、受控临时 DPI、基础命名预设、备份/恢复/管理、错误处理、中英文、诊断、可运行分发包。

GPW1 Windows 为首个验证对象，但产品结构、界面模型和测试不能硬编码为这一只鼠标。其他设备按各自证据保持读取或识别级别。公开 alpha 不以板载宏完成为前提；宏状态必须明确显示为未支持，而不是提供无法落盘的“保存成功”。

### P1：后续 alpha/beta

依次交付只读宏检查、受限板载宏写入/恢复、G-Shift、基础灯光、更多型号和平台验证。功能按独立能力上线，不把它们放在一个全有或全无的型号兼容开关里。

### 稳定 1.0

基础工作流、数据管理、安装迁移和恢复必须通过稳定门槛。至少三个鼠标家族有 Windows 基础写入/恢复证据；首批单次板载宏至少在一个明确型号/固件组合完成验证。G-Shift 和灯光不是 1.0 的硬门槛，未完成就明确不支持。

单个平台包只有达到[平台质量门槛](05-delivery.md)才能标为稳定。项目达到 1.0 不会自动提升所有平台或所有设备能力的等级。

## 3. 功能取舍

| 能力 | 确定的范围 | 排除或推迟 |
| --- | --- | --- |
| DPI | 设备能力决定范围和步长；区分当前值、默认档位、Shift 档位；保留有效当前档位 | 只因 UI 支持更大数值就允许超出设备能力 |
| 回报率 | 标准驱动先支持设备报告且已验证的档位 | 高轮询率/扩展格式需要独立驱动 |
| 按键 | 普通鼠标、键盘组合、已验证媒体动作；动作搜索与分类 | 主键丢失、未知原始动作的破坏性标准化 |
| 本地预设 | 创建、命名、复制、删除、导入导出、差异预览 | 把预设自动绑定游戏或写入新接入设备 |
| 板载槽 | 读取、编辑、保存、显式启用；显示槽号和活动状态 | 未验证的槽重排、禁用、擦除或固件级重命名 |
| 宏 | 手动编辑有界单次键盘序列；指针和未知事件只读检查 | 首版全局录制、无限循环、文本脚本、软件宏、Lua 兼容 |
| G-Shift | 后续独立第二层映射能力 | 把 DPI Shift 当作已支持 G-Shift |
| 灯光 | 后续先做已验证的关闭、亮度和静态颜色 | 首版跨设备同步、游戏联动、音乐/屏幕效果 |
| 软件模式 | 首版无常驻 | 自动应用检测、进程注入、输入钩子、自启、后台服务 |
| 其他设备 | 只读诊断可复用基础设施 | 键盘、耳机、音频处理、摄像头、方向盘的完整产品支持 |
| 更新/共享 | 手动下载安装；本地预设文件共享 | 内置社区、登录、云同步、运行时下载驱动或可执行插件 |
| 固件/配对 | 不做 | 固件升级、降级、接收器配对或解除配对 |

## 4. 默认行为

- 启动、查看设备、选择配置、切换页面、切换语言和重连不发送配置变更命令；读取 USB 报告可能唤醒设备。
- 首屏选择设备后展示当前真实状态，不自动套用“桌面默认配置”。
- 首次遇到 host 模式保留该模式。进入板载使用模式是明确动作，操作前展示活动槽变化。
- 保存备用槽保持现有活动槽、模式和当前 DPI 档位。无法满足该契约的固件路径不开放；需要切换模式或活动槽时，用户先执行独立的显式操作，再重新读取和预检。
- 修改一个按键不会默认改变当前 DPI；删除当前使用档位时，用户必须明确选择替代档位。
- 界面关闭结束本次工具进程，不缩到托盘继续运行。提交中关闭被阻止；其他退出规则见[状态契约](03-behavior.md)。
- 备份功能不要求连接设备；恢复原始备份要求同一物理设备和匹配布局。
- 软件模式未来即便加入，固定的软件配置与按应用切换也必须分别启用。

## 5. 信息架构

主界面为设备列表和工作区域。工作区域设“设备设置、按键、预设、备份、诊断”五个稳定入口；宏作为按键分配的关联编辑器，并有可复用本地宏库。灯光仅在具有相应能力时出现。

页首固定显示设备、连接状态、实际活动槽、设备模式和未保存状态。局部显示来源：设备槽、本地预设或草稿。保存按钮必须明确目标槽；启用按钮与保存按钮分开。不会用“应用”一个词同时代表三种操作。

简单操作使用紧凑表单；数值输入/滑块、二元开关、模式选择、物理位置图各司其职。预设库先按用户命名管理；应用图标、游戏封面和营销内容不进入主流程。

支持键盘导航、可访问名称、清晰焦点、缩放和中英文。不能只靠颜色表达错误、保护、活动或只读状态。设备自身名称保持原文，界面和错误阶段信息本地化。

## 6. 预设与导入体验

创建本地预设只保存语义数据，不改变设备。用户选定目标设备和板载槽后，先展示设置差异、主键保护结果、宏占用和不兼容项。默认阻止带不兼容项的写入。

允许用户显式选择仅导入兼容项，但必须列出被排除内容；绝不静默丢弃宏或重映射未知按键。跨型号按物理控制标识映射，无法映射的动作由用户重新指定。相同按键数量不是映射正确的证据。

首版不实现 G HUB 私有数据库直接导入。以后若提供转换器，也只输出可审查的本地预设，不直接向设备写入。

## 7. 不可妥协的质量顺序

数据与设备安全 > 状态正确和可恢复 > 常用流程易懂 > 响应和资源占用 > 功能覆盖。遇到取舍时，缩小开放功能或范围，不能取消冲突检测、隐藏失败或虚报兼容。
