# 04 数据、宏与恢复

状态：设计基线，关联 D08—D14。所有上限是产品输入上限，不是设备能力声明。

## 1. 数据对象

| 对象 | 主要字段与作用 | 约束 |
| --- | --- | --- |
| DeviceIdentity | 单元 ID、鼠标产品 ID 集合、型号、固件、设备类型 | 与接收器身份分开；名称不作为安全标识 |
| DeviceSnapshot | 身份、布局、完整扇区、mode、活动槽、DPI 档位 | 深复制或只读表示；作为基线与恢复证据 |
| DeviceCapabilities | 可发现的操作、值域、格式、证据决策 | 展示能力与允许变更分别记录 |
| LocalPreset | UUID、名称、schemaVersion、语义配置、能力要求、宏引用 | 不包含单元 ID、接收器路径、原始扇区 |
| MacroDefinition | UUID、名称、版本、有界事件、执行模式 | 语义定义独立于设备扇区地址 |
| Draft | 基线引用、候选语义配置、目标槽、显式状态变更意图 | 可本地暂存；不能自动提交 |
| RuntimeSession | 身份/连接代次、真实状态、预览起点和最后确认值 | 不跨进程/重连延续命令所有权 |
| WritePlan | 基线、目标、允许差异、写入顺序、恢复范围、所需能力 | 由驱动编译和验证，UI 不构造原始偏移 |
| TransactionRecord | 操作 ID、设备、备份引用、阶段、目标摘要、错误 | 不能仅凭文件存在就标记操作完成 |

原始备份继续读取 `LightHub/2`，不会为了新 UI 直接改变其有效载荷。备份名称、置顶、创建原因等存于版本化元数据索引；索引损坏不使完整备份失去可读性，保护规则仍以事务记录为准。

原始备份只恢复到同一物理设备及匹配布局。共享设置使用新的 `.lhpreset` 语义格式。字段名采用稳定英文标识，显示名称由 UI 本地化；枚举值不存储中文 UI 标签。

## 2. 文件布局与迁移

应用数据根使用各平台用户数据目录，不写程序安装目录。

```text
settings.json
presets/<uuid>.lhpreset
macros/<uuid>.lhmacro
drafts/<uuid>.json
backups/<uuid>.lhbackup
backup-index.json
transactions/<operation-id>.json
recovery/<operation-id>/...
trash/<deletion-id>/...
logs/...
```

预设/宏格式从 schemaVersion 1 开始；文档冻结字段职责，具体 JSON Schema 在 M3 随实现提交。解析必须限文件大小、嵌套深度、列表数量和整数范围。语义文件默认上限 2 MiB、JSON 深度 32；原始备份保留当前格式上限，扩大须单独审查。

写本地文件采用临时文件、刷新、原子替换，迁移前保留原件。文件系统和平台对断电持久性的保证必须验证，不能把“原子替换”宣传成跨文件/跨设备事务。索引更新采用可重建设计。

新版本遇到更高 schemaVersion 保留原件并拒绝覆盖；导入未知动作不得静默删除再保存。重命名预设改内容中的名称，不依靠文件名作为主键。删除仍被预设引用的宏必须提示解除引用或取消，不留下悬空引用。

## 3. 受限板载宏

首个可写宏能力固定为 `onboard.keyboard-sequence.single`：按一次触发一次有界序列。支持键盘 HID usage 的按下、释放，以及毫秒延时。修饰键也作为明确按下/释放事件；组合键通过事件组合表达。

首批产品上限：256 个事件、总显式延时 30 秒、单次延时 1—10000 ms、同时按下非修饰键不超过 6 个。设备驱动可以施加更严格限制，不能因产品上限更大而超出固件能力。

必须检查：usage 合法、重复按下/未按下就释放、结束时仍有按键按下、容量溢出、非法指针、循环引用、共享宏引用和未知操作码。首版不提供任意 Unicode 文本、鼠标移动、程序启动、循环、按住重复、切换重复或软件脚本。

流程先只读解析并显示现有宏，再实现本地编辑与编译，最后在恢复驱动就绪后开放设备写入。只读解析遇到未知操作码保留原始数据，停止解释相关段，不把猜测结果重新编码写回。

宏库本地编辑不会执行宏；导入、预览差异和测试解析也不触发键盘输出。第一次实际执行的验证在可控输入窗口由测试者明确触发，记录实际顺序和释放状态。没有物理执行证据，仅字节回读不能提升执行能力到稳定。

## 4. 写入计划与恢复覆盖

标准配置、宏、G-Shift、灯光分别有驱动编译器和允许修改的字节范围。驱动必须声明能否恢复计划涉及的每个区域。某区域可读取并被完整备份，不表示它可以安全改写或恢复。

写前处理：

1. 获取接收器租约和存储租约，重新读取身份、布局及操作能力。
2. 验证草稿、主键、目标槽、运行状态意图、宏引用和容量。
3. 比较完整基线内存和相关运行状态；发现外部变化则保留草稿并拒绝。
4. 编译计划，验证差异没有越过允许范围。没有变化则结束，不写日志备份、不发变更请求。
5. 持久化并重新读取备份，创建 pending 记录；存储失败则不写设备。

执行处理：

1. 写前核对目标区域仍等于预期值，每个块只发送一次变更操作。
2. 普通配置保留未修改字节；宏使用有证据的空间分配与引用更新方案。
3. 宏先写并验证数据，再更新引用它的配置，最后更新确有必要的目录。
4. 存在共享引用时不原地覆盖仍被其他槽引用的宏。优先使用已验证空闲空间；无安全空间或无恢复方案时拒绝操作。
5. 只执行用户明确请求及契约要求的运行状态操作。
6. 全量回读设备声明内存，验证目标、未知区域和运行状态；记录 complete 后才显示完整成功。

这不是对设备闪存原子提交的承诺。任何阶段断开都有可能留下部分状态。RecoveryRequired 必须阻止普通变更，并保留前状态、计划、已知阶段和错误。写入超时不触发隐式重试。

恢复时先读取和保存当前原始状态，即使某些扇区 CRC 异常也不得丢弃证据。只有恢复驱动覆盖所有差异才可执行；否则保留材料并要求进一步诊断。宏恢复同样遵守数据与指针的依赖顺序。

## 5. 备份生命周期

### 创建

普通持久保存，以及改变活动槽或模式的显式事务，均保留恢复点。临时 DPI、本地预设编辑和无变化操作不创建闪存保存备份。用户可显式创建并命名里程碑备份。

备份目录不是预设库。显示型号、时间、来源、容量、校验状态、恢复依赖、用户名称/置顶。按单元 ID 与产品 ID 组合区分物理设备，不因用户更改设备显示名称把历史拆散。

### 保留与删除

- 自动备份默认开启且不能为普通写入关闭；自动清理默认关闭。
- 手动清理默认保留每台物理设备最近 10 份自动备份。所有未完成事务引用、用户置顶、手动里程碑和无法解析的备份额外保留。
- 目标版本的普通删除进入本地回收区，保留 30 天；到期只是可清理状态，自动清理未启用时不自动擦除。
- 清空回收区或明确永久删除需再次展示文件数量、范围和不可逆性。任何恢复保护均不能被普通 UI 绕过。
- 删除/移动前在存储锁内重新读取保护引用，同时检查备份路径和 before/raw 路径。外部路径、符号链接和目录跳转不能成为清理目标。
- 恢复区、日志、事务索引容量分别展示；它们不在“旧备份清理”里被连带删除。未完成或无法解析的日志一律阻止相关清理。

现有程序实现的是确认后永久删除和手动保留 10 份，不具备回收区、命名/置顶与里程碑策略。M3 必须显式完成迁移和测试，不能把本设计写成当前能力。

### 索引与去重

首版不做跨事务物理文件去重，避免恢复引用和删除语义增加复杂度。列表索引可重建，可缓存身份/摘要以免每次设置 DPI 都解析全部文件；缓存与修改时间或内容摘要绑定，真正恢复前仍重新验证文件。

## 6. 隐私与导出

预设和宏也可能含敏感快捷键或工作内容，导出由用户发起。原始备份含单元身份和配置，不默认上传，也不作为 issue 必填附件。

诊断使用字段白名单，默认不含单元 ID、端点路径、宏正文、按键绑定、完整扇区、用户路径或进程清单。协议抓包仅在显式调试模式启用，并明确提示本地敏感数据；发布包不包含调试抓包。
